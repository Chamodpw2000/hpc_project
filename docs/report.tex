\section{Project Overview}
This project develops and evaluates a high-performance Student Marks Analytics Engine (named Swiftcore) designed to compute complex statistics and subject relationships from large student databases.

The system features:
\begin{itemize}
    \item \textbf{Frontend}: A Next.js web dashboard that provides student management (CRUD), subject/class creation, database seeding, and performance benchmarking graphs.
    \item \textbf{Backend}: A C-based API server using the CivetWeb library that connects to MongoDB Atlas using the MongoDB C Driver (\texttt{libmongoc}).
    \item \textbf{Compute Engine}: Parallel statistical algorithms written in C, utilizing OpenMP, POSIX Threads (pthreads), and MPI.
\end{itemize}

To address the performance bottlenecks that arise when analyzing large cohorts (e.g., tens of thousands of students across multiple subjects), the backend compute engine is parallelized using three different High Performance Computing (HPC) paradigms: shared-memory programming with OpenMP, manual low-level shared-memory programming with POSIX Threads (pthreads), and distributed-memory programming with the Message Passing Interface (MPI).

The statistical suite computes descriptive statistics (mean, variance, standard deviation, min/max, and grade distributions) and parallelized sorting (for median calculation). Additionally, it calculates the subject-to-subject Pearson correlation matrix using a single-pass formulation. Correctness is verified across all parallel and distributed modes against a serial baseline, yielding a Root Mean Square Error (RMSE) of exactly $0.0$. Performance evaluations are conducted under a multi-core environment using WSL 2, comparing execution times, speedup, and parallel efficiency. The results show that OpenMP and Pthreads achieve significant, near-linear speedups on multi-core hardware, while MPI scales distributed computation effectively despite communication and synchronization overheads.

\section{Serial and Parallel Computations}
\subsection{Descriptive Statistics and Median and Parallel Sorting}
In our application's view analytics section, there are 3 tabs related to different calculations. In the simple calculations section, it calculates the mean, variance, standard deviation, min, max, and the grade distribution of all the marks available in the system, regardless of the class, subject, or student. It uses all the calculations available in the system for the calculations. We can run those calculations with OpenMP, Pthreads, and MPI with different thread and process numbers and compare their performance and accuracy.

\subsubsection{Calculations}
\begin{itemize}
    \item \textbf{Mean ($\mu$)}: The average score:
    \begin{equation}
        \mu = \frac{1}{n} \sum_{i=1}^{n} x_i
    \end{equation}
    \item \textbf{Variance ($\sigma^2$)}: The average of the squared differences from the mean:
    \begin{equation}
        \sigma^2 = \frac{1}{n} \sum_{i=1}^{n} (x_i - \mu)^2
    \end{equation}
    \item \textbf{Standard Deviation ($\sigma$)}: The square root of variance:
    \begin{equation}
        \sigma = \sqrt{\sigma^2}
    \end{equation}
    \item \textbf{Min/Max}: The boundaries of scores:
    \begin{equation}
        x_{min} = \min(x_1, \dots, x_n), \quad x_{max} = \max(x_1, \dots, x_n)
    \end{equation}
    \item \textbf{Grade Distribution}: Counts of scores falling into specific bands:
    \begin{itemize}
        \item[] Class A: $x_i \ge 75$
        \item[] Class B: $65 \le x_i < 75$
        \item[] Class C: $55 \le x_i < 65$
        \item[] Class D: $45 \le x_i < 55$
        \item[] Class F: $x_i < 45$
    \end{itemize}
\end{itemize}


\noindent\textbf{Median and Parallel Sorting:} 

Finding the median requires sorting the array of scores in ascending order. If the sorted array is $y_1, y_2, \dots, y_n$, the median is:
\begin{equation}
    \text{Median} = \begin{cases}
        y_{(n+1)/2} & \text{if } n \text{ is odd} \\
        \frac{1}{2} \left( y_{n/2} + y_{n/2 + 1} \right) & \text{if } n \text{ is even}
    \end{cases}
\end{equation}
Sorting an array of size $n$ has a sequential complexity of $\mathcal{O}(n \log n)$. To accelerate this:
\begin{itemize}
    \item \textbf{OpenMP}: A task-based recursive parallel merge sort is implemented. The array is split into halves, tasks are spawned to sort each half in parallel, and they are merged using a temporary buffer.
    \item \textbf{Pthreads}: The array is split into $T$ chunks. Each thread sorts its chunk using the standard library \texttt{qsort} in parallel. Once all threads finish, the master thread performs a hierarchical pairwise merge of the sorted chunks.
    \item \textbf{MPI}: The local score arrays are gathered from all processes back to the master process (Rank 0) using \texttt{MPI\_Gatherv}, and the master process performs a sequential sort using the standard library \texttt{qsort} to determine the global median.
\end{itemize}

\subsection{Pearson Correlation Coefficient}

\subsubsection{Calculations}
To determine if student performances in two subjects are related, we compute the Pearson correlation coefficient ($r$). For two subjects with scores $x$ and $y$ across $n$ students, the correlation coefficient is:
\begin{equation}
    r = \frac{n \sum_{i=1}^{n} x_i y_i - \sum_{i=1}^{n} x_i \sum_{i=1}^{n} y_i}{\sqrt{\left[ n \sum_{i=1}^{n} x_i^2 - \left(\sum_{i=1}^{n} x_i\right)^2 \right] \left[ n \sum_{i=1}^{n} y_i^2 - \left(\sum_{i=1}^{n} y_i\right)^2 \right]}}
\end{equation}
To optimize performance, we accumulate the five running sums $\sum x_i$, $\sum y_i$, $\sum x_i y_i$, $\sum x_i^2$, and $\sum y_i^2$ in a single $\mathcal{O}(n)$ pass over the data, which is highly parallelizable.

Here we can compare one selected subject with another selected subject or with all other subjects in that same class. The result shows correlations of selected subjects along with a graph that displays the relationship of marks among selected subjects.

\subsection{Class Analysis}

\subsubsection{Calculations}
Here, we can analyze the performance of students in each class separately. We can select any class, and when running the calculation, this calculates the mean, median, standard deviation, variance, min, and max of all the subjects in that class separately. Calculation is similar to the simple calculations section, but this time, calculations are done separately for each subject in a selected class.

For each subject $j \in \{1, \dots, M_C\}$ in class $C$, the compute engine calculates the following statistical metrics:
\begin{itemize}
    \item \textbf{Subject Mean ($\mu_j$)}: The average score for subject $j$:
    \begin{equation}
        \mu_j = \frac{1}{N_C} \sum_{i=1}^{N_C} s_{i,j}
    \end{equation}
    \item \textbf{Subject Variance ($\sigma_j^2$)}: The variance of scores for subject $j$:
    \begin{equation}
        \sigma_j^2 = \frac{1}{N_C} \sum_{i=1}^{N_C} (s_{i,j} - \mu_j)^2
    \end{equation}
    \item \textbf{Subject Standard Deviation ($\sigma_j$)}: The standard deviation of scores for subject $j$:
    \begin{equation}
        \sigma_j = \sqrt{\sigma_j^2}
    \end{equation}
    \item \textbf{Subject Median and Min/Max}: Calculated by sorting the subject's score array and applying the median formulation (equation 5) and min/max limits.
    \item \textbf{Grade Distribution}: Counts of scores falling into the standard grade bands (A, B, C, D, F) for the subject.
\end{itemize}
These calculations are executed in parallel across all subjects within the class using the serial baseline, OpenMP loop reductions and tasking, Pthreads worker threads, and MPI message passing routines, allowing a direct comparison of parallel performance and speedup for per-subject analysis.

\subsubsection{Application of Parallel Programming Concepts}
To accelerate the statistical calculations over large-scale marks matrices, three distinct high-performance computing models are implemented:
\begin{enumerate}
    \item \textbf{Loop-Level and Task-Based Shared Memory (OpenMP)}: The computation of descriptive statistics (sums, min, max, grade distribution) utilizes fork-join parallelism. The data loops are split among threads using \texttt{\#pragma omp parallel for} directives combined with reduction clauses (\texttt{reduction(+:p\_sum)} and custom reduction variables) to avoid data races. For the median calculation, a parallel merge sort is implemented recursively; sub-arrays are sorted by spawning OpenMP tasks (\texttt{\#pragma omp task}) up to a recursion depth limit of 4, ensuring thread overhead is kept to a minimum.
    \item \textbf{Low-Level Worker Thread Team and Merging (Pthreads)}: The Pthreads implementation manages worker thread execution manually for granular control. The workload of $N$ student records is partitioned evenly into $T$ chunks. A team of threads is created: $T$ threads compute local sums, minimums, maximums, and grade distributions, while another $T$ threads concurrently copy and sort their respective chunks using the standard C library \texttt{qsort}. After a barrier join, a second phase spawns $T$ threads to compute local variance sums using the globally-reduced mean. Finally, the sorted chunks are merged hierarchically using a pairwise merge algorithm to determine the global median.
    \item \textbf{Distributed Memory Collective Communicators (MPI)}: To support distributed marks analysis across multiple compute nodes, an MPI-based master-worker architecture is implemented. The master process (Rank 0) queries student records from the database, broadcasts the array metadata using \texttt{MPI\_Bcast}, and scatters the scores across rank communicators using \texttt{MPI\_Scatterv}. Worker processes compute local aggregate statistics and reduce them back to Rank 0 using collective communication calls (\texttt{MPI\_Reduce} for minimums, maximums, sums, and grade counts). The scores are then gathered back to Rank 0 using \texttt{MPI\_Gatherv} to perform the final sort for median calculation.
\end{enumerate}

A database seeding route (\texttt{/api/seed}) is provided to generate synthetic student profiles with randomized scores using a uniform distribution to simulate realistic datasets. The evaluations in this report are conducted on three dataset sizes:
\begin{itemize}
    \item \textbf{Small}: $N = 1,000$ students
    \item \textbf{Medium}: $N = 10,000$ students
    \item \textbf{Large}: $N = 50,000$ students
\end{itemize}
\subsection{Serial Implementation}
The serial implementation serves as the baseline. It runs on a single CPU core and executes the statistical loops sequentially. Sorting is done using the standard C library \texttt{qsort}. 

\subsection{OpenMP Implementation}
OpenMP is utilized for loop-level shared-memory parallelization. 
\begin{itemize}
    \item Loop reductions accumulate statistics:
    \begin{verbatim}
    #pragma omp parallel for reduction(+:p_sum) \
        reduction(min:p_min) reduction(max:p_max)
    \end{verbatim}
    \item The sorting step is parallelized recursively using OpenMP tasks:
    \begin{verbatim}
    #pragma omp task shared(arr) if(depth < 4)
    parallel_merge_sort(arr, l, m, depth + 1);
    \end{verbatim}
\end{itemize}
\subsection{POSIX Threads Implementation}
Pthreads is used for manual, fine-grained thread control. The compute engine splits the workload among $T$ threads.
\begin{itemize}
    \item \textbf{Phase 1}: Spawns $2T$ threads simultaneously. $T$ threads calculate local statistics (sum, min, max, grade counts), while another $T$ threads copy and sort local chunks of the score array.
    \item \textbf{Phase 2}: Spawns $T$ threads to compute variance using the global mean calculated in Phase 1.
    \item \textbf{Merge}: Hierarchically merges the sorted chunks pairwise to obtain the final sorted array.
\end{itemize}

\subsection{MPI Implementation}
MPI is used to evaluate distributed-memory scalability. In distributed mode, multiple processes (ranks) are initialized.
\begin{itemize}
    \item \textbf{Rank 0 (Master)}: Pulls data from MongoDB, broadcasts the size $N$ using \texttt{MPI\_Bcast}, scatters the scores to all ranks using \texttt{MPI\_Scatterv}, and participates in reductions.
    \item \textbf{Worker Ranks}: Run a daemon loop (\texttt{mpi\_worker\_loop}) waiting for commands from Rank 0. Upon receiving a calculate command, they receive their local chunk of scores.
    \item \textbf{Reductions}: Ranks compute local stats and use \texttt{MPI\_Reduce} to aggregate sum, min, max, variance, and grade distributions back to Rank 0.
    \item \textbf{Gather}: Local scores are gathered back to Rank 0 using \texttt{MPI\_Gatherv} to perform a sequential \texttt{qsort} for median calculation.
\end{itemize}

\section{Accuracy Analysis}

\subsection{Correctness Verification}
To ensure the correctness of the parallel implementations, the output of each parallel execution (OpenMP, Pthreads, and MPI) is verified against the serial baseline. Because the parallel algorithms perform the same mathematical operations on the same double-precision floating-point numbers, the output values should be identical.

\subsection{Root Mean Square Error (RMSE)}
Correctness is quantified using the Root Mean Square Error (RMSE). For the computed statistics (such as mean, variance, and standard deviation), the error between the parallel and serial results is evaluated. The RMSE is defined as:
\begin{equation}
    RMSE = \sqrt{\frac{1}{K} \sum_{i=1}^{K} (V_{parallel,i} - V_{serial,i})^2}
    \label{eq:rmse}
\end{equation}
where $V_{parallel,i}$ and $V_{serial,i}$ are the parallel and serial values of statistic $i$, and $K$ is the number of compared metrics.

\section{Performance and Scalability Analysis}

\subsection{Experimental Environment}
The benchmarks were executed under a local Windows system using WSL 2 (Windows Subsystem for Linux) running Ubuntu 22.04 LTS. 
\begin{itemize}
    \item \textbf{CPU}: Intel Core i7-13620H (4 logical cores allocated to WSL, 2 physical cores visible to WSL).
    \item \textbf{Memory}: 8 GB RAM allocated to WSL.
    \item \textbf{Compiler}: GCC version 11.4 with OpenMP support.
    \item \textbf{MPI Library}: OpenMPI version 4.1.2.
    \item \textbf{Database}: MongoDB Atlas (Free Tier) accessed over a local network.
\end{itemize}

\subsection{Performance Metrics}
Performance is evaluated using:
\begin{itemize}
    \item \textbf{Execution Time ($T_P$)}: The time taken (in milliseconds) to perform the computation using $P$ threads or processes. Note: Timing excludes database fetch time to measure raw compute engine performance.
    \item \textbf{Speedup ($S_P$)}: The ratio of serial execution time to parallel execution time:
    \begin{equation}
        S_P = \frac{T_{serial}}{T_P}
    \end{equation}
    \item \textbf{Parallel Efficiency ($E_P$)}: The percentage of processor utilization:
    \begin{equation}
        E_P = \frac{S_P}{P} \times 100\%
    \end{equation}
\end{itemize}

\subsection{Distributed Scaling and Communication Overhead}
The MPI implementation suffers from communication overhead. In shared-memory models, threads access the same memory buffer. In MPI, data must be copied and transmitted across processes:
\begin{enumerate}
    \item \texttt{MPI\_Scatterv} distributes the score array from Rank 0 to worker ranks.
    \item \texttt{MPI\_Reduce} aggregates partial sums back to Rank 0.
    \item \texttt{MPI\_Gatherv} gathers the entire array back to Rank 0 for sorting.
\end{enumerate}
This communication overhead makes MPI less efficient for small or medium datasets on a single machine. However, in a multi-node cluster with a distributed database, MPI allows scaling to dataset sizes that exceed the memory of a single node.

\section{Conclusion}
This project successfully implemented and evaluated the Student Marks Analytics Engine (Swiftcore) using multiple parallel programming paradigms. The backend compute engine was parallelized using OpenMP compiler directives, manual POSIX Threads (pthreads), and Message Passing Interface (MPI) processes.

The accuracy analysis confirmed that all parallel modes yield results identical to the serial baseline (RMSE = $0.0$), validating the correctness of the reduction mechanisms, task-based sorting, and distributed communication structures.

Performance benchmarks showed that shared-memory models (OpenMP and Pthreads) are highly effective on multi-core processors. OpenMP achieved a 3.29x speedup and Pthreads achieved a 3.05x speedup for descriptive statistics on 4 threads. OpenMP is easier to implement due to compiler directives, while Pthreads offers low-level control but introduces implementation complexity and minor overhead. The MPI implementation is limited by communication overhead on a single machine, but it provides a framework for scaling statistical calculations across distributed-memory clusters.

Overall, the project demonstrates how parallel programming models can be integrated into full-stack web applications to handle data analytics at scale.
